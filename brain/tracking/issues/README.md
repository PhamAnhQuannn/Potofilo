# Issues — Việc liên quan phát sinh (tạm thời)

Khi bắt đầu một việc/thay đổi, lúc đánh giá tác động (xem `.claude/rules/workflow.md`) có thể lộ ra **việc liên quan khác cần làm**. Ghi chúng ở đây để không quên.

Đây là chỗ **tạm**: issue xong sẽ chuyển thành report và **file issue bị xóa**.

## Vòng đời 1 issue
1. **Phát sinh** — trong lúc đánh giá tác động của một việc.
2. **Ghi lại** — tạo file `NNNN-<mo-ta-ngan>.md` ở đây, viết dễ hiểu cho non-tech (theo `.claude/rules/writing.md`).
3. **Xử lý** — giải quyết issue.
4. **Đóng** — viết báo cáo ở `brain/tracking/reports/NNNN-*.md`, thêm dòng vào `reports/README.md`, rồi **XÓA file issue này** + xóa dòng khỏi bảng dưới.

## Quy tắc
- 1 file = 1 issue liên quan.
- Chỉ ghi issue thật sự dính tới việc đang làm (đúng phạm vi — xem `workflow.md`).
- Issue là bản tạm; nguồn lâu dài là report + CHANGELOG.

## Khung 1 issue
```
# NNNN — <tên dễ hiểu>
- Ngày phát hiện:
- Lộ ra từ việc: <việc nào làm phát sinh issue này>
- Trạng thái: mở / đang xử lý

## Vấn đề là gì
(kể dễ hiểu, non-tech đọc cũng hiểu)

## Vì sao liên quan
(nó dính tới việc đang làm ra sao)

## Nếu không xử lý thì sao
## Hướng xử lý dự kiến
## Từ ngữ (nếu có từ khó)
```
